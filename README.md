# Processor.Ai

> Методическое пособие о том, как научиться вычислять простейшие математические выражения. Например 2 + 2 или (4 - 5)/3, для этого достаточно просто написать собственный виртуальный процессор и все сразу решится само собой!

## Описание проекта
Здесь реализована тьюринг-полная стековая виртуальная машина с собственной системой команд представленной в разделе `Система команд`. В процессоре есть 4 регистра, доступна работа с RAM, а также присутствует видеопамять (реализована через отрисовку оперативной памяти). Присутствует программа ассемблера и дизассемблера.
В разделе `Examples` есть примеры программ, работающих на моем процессоре.

Кусок кода программы для подсчета факториала представлен ниже:
```asm
CALL :factorial
OUT 
HLT

:factorial
POP RAX
PUSH RAX
PUSH 1       
    JA :recursion
    PUSH 1

RET
```

## Архитектура процессора
Структура процессора состоит из:
* массива регистров: `RAX`, `RBX`, `RCX`, `RDX`
* стека для вычислений с элементами типа double 
* стека для адресов возврата
* сегмента кода
* указателя на текущую инструкцию (IP)
* длины кода
* указателя на оперативную память RAM

## Архитектура программы
В заголовочном файле Includes.h подключаются необходимые библиотеки. В остальных заголовочных файлах находятся все обьявления и константы, связанные соотвественно с процессами Ассемблирования, Дизассемблирования, Исполнения, Чтения, Операций со стеком и Видео Памятью.

## Логика работы
* В файле с разрешением `.asm` содержится набор команд для процессора. Модуль `Assembler.cpp` читает этот файл с помощью модуля `Reading.cpp`, далее анализирует каждую прочитанную строку как команду с аргументом (или без него). Для каждой команды определяется ее номер, этот номер записывается в сегмент кода процессора по индексу `IP`. Когда считан номер, читается аргумент, который в свою очередь тоже записывается в сегмент кода по индексу `IP + 1`.
Ассемблер делает два прохода, чтобы обработать метки, которые описаны после своего появления в файле `.asm`. На втором проходе также происходит запись кода в файл `code.txt`, где каждая строка записывается в формате "Номер команды_Аргумент команды".
* Далее происходит исполнение прочитанных команд с помощью модуля `Processor.cpp`. Исполняется команда, на которую в текущий момент указывает `IP`, затем этот индекс сдвигается - это происходит до момента, пока не прочитана инструкция HLT или пока не достигнут конец сегмента кода.
* Следующим запускается модуль Дизассемблирования `DisAssembler.cpp`, который проходит по Сегменту Кода и последовательно дизассемблирует каждую команду со своим аргументом в файл `code.disasm`.
* В самом конце вызывается модуль видео памяти, который выводит на экран графическое представление RAM.

## Режимы компиляции и запуска
* Компиляция программы происходит с помощью скриптов `build.sh` и `build_debug.sh`. Внутри обоих можно убрать/вставить флаги `STACK_DEBUG`, `PROCESSOR_DEBUG`, `ASSEMBLER_DEBUG` и `GRAPHICS_FLAG` и тогда отключатся/подключатся соответствующие возможности: отладочная информация для стека, процессирования, ассемблирования и отрисовка RAM. 
* В программе есть возможность при запуске задавать файл для исполнения, для этого достаточно написать 
```bash
./a.out <путь_к_файлу.asm>
```
Если не передать имя файла явно, то используется по умолчанию файл `examples/code.asm`.


## Система команд
Номера в списке соответствуют реальным номерам команд.
Исключение составляют команды `PUSH` и `POP`, описание номеров команд для которых указано ниже.

0) HLT - завершает работу программы

1) PUSH - кладет элемент в стек
Команда PUSH кодируется 1 байтом, где 5 младших бит отведены под номер команды `00001`, а 3 старших отвечают соответственно за обращение к стеку (5-й бит), за обращение к регистру (6-й бит) и к оперативной памяти (7-й бит). Причем старшие биты в некоторой комбинации могут быть включены одновременно, например команда PUSH может иметь номер `0b11000001` при вызове PUSH [RAX], эта команда пушит в стек число которое лежит в оперативной памяти по адресу, хранящемся в регистре `RAX`.
Возможные коды команды:
* `0b00100001` - положить обычное число в стек
* `0b01000001` - положить число, лежащее в регистре в стек
* `0b10100001` - положить элемент, лежащий по заданному адресу в `RAM`. Например `PUSH [4]`.
* `0b11000001` - положить элемент, лежащий по адресу в `RAM`, содержащемуся в заданном регистре. Например `PUSH [RAX]`.

2) POP - забирает элемент из стека. При отсуствии аргументов просто забирает элемент, а при наличии аргумента-адреса, например как в команде `POP RCX`, забирает элемент из стека и кладет в `RCX`. 
Кодирование команды `POP` полностью аналогично команде `PUSH` за исключением того факта, что бит, отвечающий за то чтобы положить просто число в стек отсуствует.
Возможные коды команды:
* `0b10100002` - взять элемент со стека и положить в `RAM` по заданному адресу, например `POP [7]`.
* `0b11000002` - взять элемент со стека и положить в `RAM` по адресу из заданного регистра, например `POP [RBX]`.
* `0b01000002` - взять элемент со стека и положить в заданный регистр, например `POP RCX`.

3) ADD - берет из стека два числа, складывает и кладет результат обратно в стек

4) SUB - берет из стека два числа, вычитает одно из другого и кладет результат обратно в стек

5) DIV - берет из стека два числа, делит одно на другое и кладет результат обратно в стек

6) MUL - берет из стека два числа, перемножает и кладет результат обратно в стек

7) JMP - ставит `IP` на указанный адрес 

8) JA - берет из стека два числа, если первое из них больше второго, выполняет `JMP`

9) JAE - берет из стека два числа, если первое из них больше второго или равно ему, выполняет `JMP`

10) JB - берет из стека два числа, если первое из них меньше второго, выполняет `JMP`

11) JBE - берет из стека два числа, если первое из них меньше второго или равно ему, выполняет `JMP`

12) JE - берет из стека два числа, если числа равны, выполняет `JMP`

13) JNE - берет из стека два числа, если числа не равны, выполняет `JMP`

14) OUT - берет число из стека и выводит его в `stdout`

15) IN - принимает на вход число из `stdin` и кладет его в стек

16) CALL - вызывает функцию с указанной меткой, кладет адрес возврата в стек адресов возврата

17) RET - берет из стека адресов возврата нужный адрес и делает `JMP` по этому адресу

## Формат видеопамяти
Видеопамять реализована с помощью цветного вывода оперативной памяти в консоль. Если элемент в памяти нулевой, то он изображается белым "пикселем" (просто символ, закрашенный в белый на белом фоне), если элемент ненулевой, то его значение используется как индекс в массиве `Palette` для получения цвета, после чего этот символ выводится опять же как пиксель соответствующего цвета.
Для задания цвета конкретной ячейки можно передать в оперативную память нужный цвет по индексу в нужный адрес. Координата ячейки рассчитывается по формуле:
`address = row * NumCols + col`
Обратное преобразование:
`row = address / NumCols`
`col = address % NumCols`
Причем `NumCols` равен `20`.

Реализовать задание цвета нужной координате можно комбинацией двух команд, пример ниже:
```asm
PUSH 1
POP [5]
```
Эта программа кладет в пятую ячейку оперативной памяти число 1. Это значит, что при отрисовке 5-я ячейка (с координатами (0, 5)) получит цвет из `Palette[1]`, а именно `0x0000AA` - темно-синий.

## Обработка ошибок 
Если включить в файле `build_debug.sh` флаги `STACK_DEBUG`, `ASSEMBLER_DEBUG`, `PROCESSOR_DEBUG`, то при возникновении ошибки пользователь увидит отдельные дампы и сообщения об ошибках для каждого типа ошибок.
Например при допущении синтаксической ошибки, программа выведет следующее сообщение:
```bash
Assembly Error: Syntax Error at line 2 in file examples/code.asm
```
Любую ошибку, связанную со стеком вычислений можно отследить в файле `dump.txt`, где представлена подробная информация о стеке в момент "снимка".
При включении флага `PROCESSOR_DEBUG` в консоль при каждом нажатии на клавишу будет выводится дамп сегмента кода, где символ `<` указывает на текущую исполняемую инструкцию, таким образом можно отследить исполнение программы процессором. Сам дамп ограничен `N` символами и центрируется вокруг `IP`.

## Дизассемблер
Ниже представлен сначала пример ассемблерного кода, а затем дизассемблированного:
#### Ассемблер
```asm
IN
POP RAX                    ; RAX = n
CALL :fib 
PUSH RBX
OUT
HLT 
```

#### Дизассемблер
```asm
IN
POP RAX
CALL 9
PUSH RBX
OUT
HLT
```
Замечу, что `CALL 9` в дизассемблере вместо `CALL :fib` - это не баг, а ожидаемое поведение, так как мой дизассемблер не отслеживает имена меток - он проходит циклом по сегменту кода, который ничего не знает о метках, информация о них теряется в процессе ассемблирования и остаются только голые адреса (индексы в массиве сегмента кода).
