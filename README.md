# Processor.Ai

> Методическое пособие о том, как научиться вычислять простейшие математические выражения. Например 2 + 2 или (4 - 5)/3, для этого достаточно просто написать собственный виртуальный процессор

## Описание проекта
Здесь реализована тьюринг-полная стековая виртуальная машина с собственной системой команд.
### Особенности
* 4 Регистра общего назначения (`RAX`, `RBX`, `RCX`, `RDX`)
* Стек для вычислений типа `double` и стек для адресов возврата
* Работа с оперативной памятью (`RAM`)
* Видеопамять: вывод `RAM` в консоль в графическом виде
* Двухпроходный ассемблер и дизассемблер
* Примеры рабочих программ в папке `examples/`
<details>
<summary><b>Пример программы: вычисление чисел Фибоначчи (нажмите, чтобы развернуть)</b></summary>

```asm
IN
POP RAX                         ; RAX = n
CALL :fib 
PUSH RBX
OUT
HLT 

:fib 
    PUSH RAX                    ; случай n = 0
    PUSH 0
    JNE :else1
    PUSH 0
    POP RBX
    RET

    :else1                      ; случай n = 1
        PUSH RAX
        PUSH 1
        JNE :else2
        PUSH 1
        POP RBX
        RET

        :else2
            PUSH RAX            ; основной случай
            PUSH RAX
            PUSH 1
            SUB                 ; в стеке лежит n n-1
            POP RAX             ; в стеке лежит n, а в RAX лежит n-1
            CALL :fib

            POP RAX             ; стек пуст, а в RAX лежит n
            PUSH RBX            ; в стеке лежит значение RBX

            PUSH RAX            ; в стеке лежит RBX n 
            PUSH 2              ; в стеке лежит RBX n 2
            SUB                 ; в стеке лежит RBX n-2
            POP RAX             ; в RAX лежит n-2, а в стеке RBX
            CALL :fib 

            PUSH RBX
            ADD
            POP RBX
            
            RET
```
</details>

## Архитектура процессора
Структура процессора состоит из:
* массива регистров: `RAX`, `RBX`, `RCX`, `RDX`
* стека для вычислений с элементами типа double 
* стека для адресов возврата
* сегмента кода
* указателя на текущую инструкцию (IP)
* длины кода
* указателя на оперативную память RAM

## Логика работы
* В файле с разрешением `.asm` содержится набор команд для процессора. Модуль `Assembler.cpp` последовательно читает эти команды, переводит их в номера инструкций и записывает в сегмент кода. Для качественной обработки меток используется 2 прохода ассемблера.
* Далее происходит исполнение прочитанных команд с помощью модуля `Processor.cpp`. Исполняется та команда, на которую в текущий момент указывает `IP`.
* Следующим запускается модуль Дизассемблирования `DisAssembler.cpp`, который проходит по Сегменту Кода и последовательно дизассемблирует каждую команду со своим аргументом в файл `code.disasm`.
* В самом конце вызывается модуль видео памяти, который выводит на экран графическое представление RAM.

## Режимы компиляции и запуска
* Компиляция программы происходит с помощью скриптов `build.sh` и `build_debug.sh`. 
* Сборка в релизном режиме
```bash
./build.sh                  // Релизный режим
./build_debug.sh            // Отладочный режим 
```
* В программе есть возможность при запуске задавать файл для исполнения, для этого достаточно написать 
```bash
./a.out <путь_к_файлу.asm>
```
Если не передать имя файла явно, то используется по умолчанию файл `examples/code.asm`.

## Требования
* **Компилятор** Для сборки необходим компилятор с поддержкой **C++17**, например `g++` или `Clang`
* **ОС** Linux/macOS, так как в программе используются системные вызовы `open()`, `read()` и `close()` а также заголовки вроде <unistd.h> и <sys/stat.h>.
* **Библиотеки** `libm` для математических функций

## Система команд
Номера в списке соответствуют реальным номерам команд.
Исключение составляют команды `PUSH` и `POP`, номера которых зависят от типа аргумента к которому они применяются.

0) HLT

1) PUSH

2) POP 

3) ADD 

4) SUB

5) DIV

6) MUL 

7) JMP

8) JA

9) JAE

10) JB 

11) JBE 

12) JE 

13) JNE 

14) OUT 

15) IN 

16) CALL

17) RET 

## Формат видеопамяти
Видеопамять реализована с помощью цветного вывода оперативной памяти в консоль. Если элемент в памяти нулевой, то он изображается белым "пикселем" (просто символ, закрашенный в белый на белом фоне), если элемент ненулевой, то цвет берется из массива `Palette`.

Реализовать задание цвета нужной координате можно комбинацией двух команд, пример ниже:
```asm
PUSH 1
POP [5]
```
Эта программа кладет в пятую ячейку оперативной памяти число 1. Это значит, что при отрисовке 5-я ячейка (с координатами (0, 5)) получит цвет из `Palette[1]`, а именно `0x0000AA` - темно-синий.

## Обработка ошибок 
За обработку ошибок отвечают флаги `STACK_DEBUG`, `PROCESSOR_DEBUG`, `ASSEMBLER_DEBUG`, которые позволяют явно увидеть где возникла ошибка соответствующего характера.
Например при допущении синтаксической ошибки, программа выведет следующее сообщение:
```bash
Assembly Error: Syntax Error at line 2 in file examples/code.asm
```
А ошибки со стеком можно легко отследить в файле `dump.txt`.

## Дизассемблер
Ниже представлен сначала пример ассемблерного кода, а затем дизассемблированного:
#### Ассемблер
```asm
IN
POP RAX                    ; RAX = n
CALL :fib 
PUSH RBX
OUT
HLT 
```

#### Дизассемблер
```asm
IN
POP RAX
CALL 9
PUSH RBX
OUT
HLT
```
Замечу, что `CALL 9` в дизассемблере вместо `CALL :fib` - это не баг, а ожидаемое поведение, так как мой дизассемблер не отслеживает имена меток - он проходит циклом по сегменту кода, который ничего не знает о метках, информация о них теряется в процессе ассемблирования и остаются только голые адреса (индексы в массиве сегмента кода).
